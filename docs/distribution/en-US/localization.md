# US English localization coverage

Development record · September 14, 2026

Use the [current operating guide](manual.md) for installation and product workflows. This record describes the source-level English pass; it is not evidence that every native window, remote environment, or external provider has been visually verified.

## Default and scope

US English is the default for new settings. Launch with `--language en-US` (or `--language us-en`) to explicitly select it. Existing saved language choices remain available. The multilingual catalogs retain their existing keys and language entries; this work does not certify complete coverage in the other languages.

The pass covers first-party interface labels, headings, help text, action previews, notices, errors, and report templates in the desktop workspace and specialist panels: connection setup, remote tools, session windows, inventory and vault access, recordings, local OCR, team collaboration, job execution, diagnostics, recovery plans, clone rehearsals, background recovery, ticket integration, workflows, and teaching. Domain messages and AI instructions were audited as well, because a translated panel can still display a message produced elsewhere.

The work uses explicit, reviewed English source text. There is no runtime translation service or automatic word-replacement layer. Complete literals and sentence templates were translated with their action, prerequisites, and limitations intact. Format markers such as `{}`, `{name}`, and `{:?}` were compared against their original counterparts so that values keep the same bindings. Protocol commands, file paths, serialized keys, identity fields, and persistence identifiers were preserved. Display-text assertions were updated where only the wording changed; behavior assertions remain necessary independently of localization.

## Intentional retained text

- Localization lookup keys and non-English catalog entries remain in source. Their presence does not mean the US English interface displays those entries.
- Compatibility matching retains selected legacy German values, including old status strings and search terms. Removing those matches could break previously stored data. English equivalents are accepted where required.
- Test fixtures retain multilingual input where it exercises Unicode handling, persisted content, or untrusted input. A fixture is not a new interface label.
- Historical engineering documents and the September 13 distribution snapshot retain their original wording and language. The current guide supersedes that snapshot for current operation.
- Names, notes, imported tickets, recordings, remote screen contents, and other user or source data are not rewritten. Existing stored reports and previously generated AI text also retain their original content.

Windows, PowerShell, protocol libraries, remote servers, and external providers may return messages in their configured language. Optional AI output is requested in US English, but provider output is external content and is not a guaranteed translation. Those messages must be distinguished from first-party English templates when reviewing a screen.

## Verification and limits

The source audit combined searches for German characters with searches for ASCII German words and transliterations. `scripts/audit-english.py` provides a review queue, not a complete language detector or a localization proof. Raw strings, short labels, historical compatibility values, and dynamically assembled messages require manual classification.

Changed panel templates passed a comparison of their format markers, and the patch was checked for whitespace errors. Automated tests validate selected rendered labels and model behavior; the build's current test results belong in the [acceptance record](acceptance.md). Source review and passing tests do not establish that every panel, dialog, DPI setting, error path, or live remote session has been visually checked. In particular, longer English text can still require layout review at supported window sizes and display scales.

For a newly found language issue, record the exact visible text, panel, selected language, build identifier, and whether the message was generated by Relayne, loaded from existing data, or supplied externally. Update the complete first-party template and any corresponding display assertion, then verify the affected view. Do not translate protocol payloads or historical records merely to make a text search return no matches.
