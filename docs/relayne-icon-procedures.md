# Local icon anchors and workflow procedures

Teaching can propose a textless icon when the original demonstrated click has no usable text anchor. A proposal is a fixed 24×24 RGB crop from that exact displayed frame. Matching OCR must report no word overlapping the crop, and the crop must not intersect the sensitive redaction bands. Low-contrast/flat templates and ambiguous source matches are refused. The enlarged crop is shown for explicit review before it replaces a coordinate step; OCR is heuristic, so the reviewer must confirm it contains only a nonconfidential icon. Unapproved crops stay in memory. Approved templates are stored in the DPAPI procedure library; portable workflow packages include their reviewed pixel data.

Replay searches the current destination frame locally with a bounded pixel comparator. Confidence is one minus normalized RGB absolute error. The best match must reach 97.5%, and a spatially separate candidate within two percentage points refuses the action. Frames are capped at 32 MiB and full candidate comparisons at 4096. Missing icons, changed colors/themes, duplicate icons and insufficient confidence stop the run. Templates currently require the same pixel size; there is no scale/rotation or semantic icon inference. Existing per-step and final OCR postconditions still determine visible completion.

A workflow can embed the demonstrated Procedure with an exact host and parameter-name-to-runtime-slot mapping. Inert validation caps the procedure at 192 KiB, validates all step types, requires every step's visible postcondition plus a final visible condition, and rejects unknown parameters. Runtime dispatch requires exactly one already connected direct RDP session for the host. It binds the selected session and current profile identity to the full procedure and in-memory parameter values through the existing five-minute RunApproval. It neither opens a new connection nor embeds parameter values in saved procedures.

The application exposes start_workflow_procedure, workflow_procedure_status and cancel_workflow_procedure for the workflow panel. Status remains pending until the teaching runner verifies its final visible condition, or reports failure/cancellation on drift, disconnect, missing fresh OCR, timeout, policy refusal or manual interruption. The workflow must not substitute a manual checkpoint acknowledgment for this completion result. Visible OCR conditions establish observed UI state, not backend transaction causation.

Synthetic tests move a distinctive icon, add a duplicate, omit it, change its colors, and reject a flat template. Existing teaching/transferable tests cover frame freshness and run-approval binding. No live remote mutations are performed by these tests.
