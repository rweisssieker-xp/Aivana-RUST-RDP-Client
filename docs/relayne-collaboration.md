# Relayne live co-working

Configure the existing authenticated Team origin and bearer token. Open Team and enter exact actor identities (comma-separated) before explicitly sharing the selected connected RDP session. Capture must pass local redaction before publication. The room ID is an invitation locator, not authorization: only the owner and its allowlisted actors can view it. Joining displays actual latest sanitized RGB pixels. Enter an annotation then click its position; annotations use normalized coordinates.

The owner grants one member an exclusive 20-second control lease. That member needs an operator/admin role. With an empty annotation field, clicking the shared image proposes a single left click against the immutable session, source-frame hash, coordinates, and lease generation. The navigation buttons can instead propose Enter, Tab, Escape, arrows, Home, End, PageUp, PageDown or F5. The exact key is included in the immutable digest. Two distinct authenticated operator/admin actors must approve the displayed SHA-256 digest. The owner explicitly consumes the approved request once and applies local session/frame/policy checks immediately before dispatch. Held local inputs are released before and after dispatch, and concurrent teaching replay is stopped. A key has a paired press/release; free typing, clipboard contents and arbitrary commands are not transmitted.

Frames use bounded zlib compression encoded as Base64, with a strict 691,200-byte decompression cap. Update scheduling is 200 ms with at most one capture worker and one request in flight. Every published image still passes local OCR/redaction. A completed sanitized image may be shown for up to two seconds while the next image is processed; execution always requires the current source frame hash. The actual update rate depends on OCR, network and renderer latency; this is not a high-frame-rate video stream. **Update desktop client and team server together:** the compressed wire format is not compatible with the previous JSON byte-array format.

Revocation, controller departure, revoked controller identity, lease expiry and changed source frame invalidate pending proposals. Consumption is server-serialized and cannot replay. A click already consumed/dispatched cannot be recalled by a later revoke; this is the normal distributed-operation boundary. Actor identity uniqueness and token assignment are the administrator's responsibility: two tokens assigned the same actor do not count as two approvers. The protocol does not prove that two humans are behind two admin-provisioned identities.

Rooms expire after 30 seconds without owner traffic; leases cannot auto-renew. Owner polls/publications keep the room alive only while its Team view is active. Explicit leave closes an owner room, or removes a member and its lease. Lost network/UI exit revocation is bounded by these timeouts, not instantaneous. An authorization/network error clears local sharing state and cannot trigger offline execution. Restart clears all rooms (SQLite TEMP storage); frame content is not put in the persistent application tables or audits. SQLite TEMP storage is configured in memory. Reverse proxy request logging must not capture bodies or bearer headers. Remote origins require HTTPS.

Bounds: 32 active rooms, 16 invited identities each, 640×360 RGB frame, 3 MB request body, 64 annotations (200 characters), 16 proposals, normalized coordinates 0..10000. Redaction quality depends on the configured OCR/masking engine; the server validates shape and cannot independently certify sanitized content. This is deliberate consented collaboration, not a claim of perfect data-loss prevention.

Verification includes in-memory authenticated-role fixtures for membership, limits, lease/disconnect invalidation, immutable digests, same-identity duplicate approval, two-party consumption and replay rejection, plus loopback HTTP coverage for missing/revoked authentication, viewer denial, unauthorized membership, and actual published/viewed frame bytes.

Client consent is bound to the locally selected session. Joining a room under its owner's identity does not authorize local publication or execution. Changing the selected session closes a locally shared room before any capture of the new selection. Replies are bound to the pending request/room; execution requires the exact pending consumption and an unexpired matching lease. Client response size and image shape are checked before rendering. Token revocation invalidates that actor's old votes and leases even when another token exists; departing members lose their approvals.
