# Relayne local screen understanding

Relayne calls Windows.Media.Ocr locally through the windows 0.61 crate. The worker initializes a WinRT MTA, converts RGBA to BGRA in memory, creates SoftwareBitmap from DataWriter/IBuffer and invokes OcrEngine.TryCreateFromUserProfileLanguages / RecognizeAsync. No screen is uploaded, and OCR input is not written to temporary files. Windows 10/11 and an installed OCR language package are required. Oversized images fail against OcrEngine.MaxImageDimension rather than silently scaling coordinates.

The Bild verstehen panel requests OCR asynchronously for the selected session. Words have pixel bounds, image dimensions, session ID, capture timestamp and frame hash. A changed capture invalidates OCR even if the dimensions are unchanged. Reading an old result is allowed; using it for a semantic action is blocked.

Teaching supports explicitly binding the next click to an exact normalized OCR word plus optional nearby context word (within 500 horizontal / 120 vertical pixels). Exactly one candidate must remain. Missing or ambiguous targets stop execution. The fresh word bounds determine the click center, so layout movement does not reuse the demonstrated coordinate. Each step still requires explicit review. Coordinate and semantic approvals bind session, timestamp and hash; a changed frame clears the approval. Labels are chosen by the user: demonstrated clicks are not silently converted to semantic targets. Multiword OCR phrases, icons without text and semantic meaning inference are not implemented.

Recording runs OCR on each queued keyframe before PNG encoding. Detected credential labels, token-like strings, long digit strings, masked-password glyphs and long mixed alphanumeric values trigger a broad full-width band mask including the field and lines below. Those OCR words and all words intersecting manual masks are removed before building the searchable index. The PNG and index are DPAPI protected. Existing recordings remain readable with an empty OCR index. OCR failures stop collection; raw screenshots are never saved as a fallback. Search text is bounded to 4,096 characters per frame. This is conservative heuristic redaction, not proof that every secret was found: unreadable/custom controls, unexpected labels and image-only secrets can escape OCR. Manual masks remain important. No cloud OCR is configured.

Tests cover typed fake word bounds, moved labels, missing/duplicate labels, stale frame rejection, sanitized index and masked PNG pixels. A generated nonsecret Arial fixture in tests/fixtures/ocr-nonsecret.png exercises the actual Windows OCR API and exact-word/context resolution. It intentionally fails if the local OCR language package/API is unavailable; it is not mocked. No live RDP session or credentials are used.

Validation on 2026-09-11: cargo test --offline vision passed 4/4 tests, including actual Windows.Media.Ocr recognition of the generated nonsecret fixture. OCR runs on a worker with a 20-second recognition deadline and cancellation request. No live remote connection was used.
Validation also passed cargo test --offline teaching (9/9) and cargo test --offline recording (5/5 matching tests, including four recording tests). The recording roundtrip uses real local OCR and Windows DPAPI, then reads the protected keyframe and index back.
