# Expert procedure compiler

Open **Anlernen → Expertenverfahren mit KI kompilieren** after finishing a demonstration, its success/recovery notes and visible anchors. Explain which inputs vary and which visible states establish success. The panel shows the complete outbound metadata and explanation before the one-request OpenAI consent checkbox. It uses the configured OpenAI model and `OPENAI_API_KEY`; nothing calls the provider until the operator requests a proposal.

The typed proposal can name existing unnamed text placeholders and attach existing visible anchors to known steps or the final result. It cannot add actions, commands, input values, target identities, labels, or replace existing assertions. Ambiguous proposals abstain and display missing information. Unanchored clicks and navigation still need the existing manual conversion/review process before a whole procedure is eligible to run.

Inspect parameter edits, assertion mappings, reasons and assumptions. Parameter names are editable, which clears the review checkbox. After explicit review, adopt into the learning draft, then use the existing encrypted library save or workflow preparation controls. Adoption clears previous replay approvals, target selection and queued targets; execution needs fresh existing workflow/target authorization. A changed demonstration, explanation or model discards consent and the proposal.

Provider requests have a 90-second timeout, redirects disabled, a 256-KiB response cap and strict JSON output validation. Only displayed metadata is transmitted: no frame pixels, icon templates, runtime parameter values, profile records or session identities. Operator explanation and anchor text are visible for review and must not contain secrets. Compiler results are proposals, not proof of observed success. Fixture tests exercise bindings, input minimization, ambiguity, invalid references, malformed/refused responses and consent invalidation. No live provider execution is required for development tests.
