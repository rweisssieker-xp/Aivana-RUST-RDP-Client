# Change Time Machine

The Change History panel runs local Windows PowerShell or remote WinRM Negotiate under the current Windows identity. It captures an existing file's exact bytes, one typed registry value, or one file's owner/group/DACL SDDL, and requires explicit review before applying. Snapshots and replacements are limited to 1 MiB each. The comparison shows byte lengths and SHA-256 fingerprints; optional reveal displays contents in memory. The text editor replaces the entire UTF-8 content, including line endings; original file snapshots and restoration remain byte exact, including binary content.

Existing REG_SZ, REG_EXPAND_SZ, REG_DWORD, REG_QWORD, REG_MULTI_SZ and REG_BINARY values are supported. Select the actual existing type: type conversion, new values and deleted registry values are not supported. Strings preserve environment-variable expressions without expansion; integer input is unsigned decimal across the full 32/64-bit range; MULTI_SZ input is a JSON string array; BINARY input is Base64. Canonicalized values are reviewed and compared before writing. Registry keys and trees are never recursively restored.

Before mutation, Relayne rechecks the snapshot, encrypts the full entry with the current user's Windows DPAPI, and commits a synchronized temporary journal file with atomic rename. Failure to persist prevents mutation. Each operation compares exact current bytes again at the target and verifies the after state. File operations hold an exclusive stream during compare/write/verification. Registry operations check value kind and content immediately before writing; competing registry writers must be paused because there is no equivalent exclusive lock.

The application data directory's change-history folder holds UUID-named .dpapi entries: at most 128 entries and 128 MiB total encrypted storage. Each encrypted entry is capped at 10 MiB, allowing JSON byte-array serialization of two 1 MiB snapshots. Loads validate IDs, paths and snapshot limits. There is no plaintext snapshot export. Incident reconstruction receives only target metadata, timestamps, byte lengths and fingerprints. DPAPI requires the original Windows user context. Production persistence is disabled off Windows.

Restoring requires separate explicit review. Existing targets must match the recorded after content. An already matching before state resolves the entry without mutation; other content is a conflict. Restoration journals its pending state before touching the target. Prepared or RestorePending entries after failure remain recoverable through the same checks; they do not claim mutation succeeded. Reload the journal after failure.

File snapshots also record original owner/group/DACL and the exact parent directory path and owner/group/DACL. Review-to-apply checks reject changed security metadata. A reviewed restoration can recreate an externally deleted file from this snapshot, only at the recorded path with an existing unchanged parent and no reparse points anywhere along that path. Creation uses CreateNew and supplies the original security descriptor at creation, followed by ACL and byte verification. Missing privilege, a replaced parent ACL, an existing target, or an unsupported path fails the operation. Old journal entries without security metadata cannot recreate deleted files. Recovery does not include timestamps, alternate streams, hard-link identity, SACL, directory trees, deleted registry objects, or arbitrary application state.

Explicit file-permissions mode reviews canonical owner/group/DACL SDDL and changes DACL/inheritance on one existing file. Owner and group must remain unchanged; ownership reassignment is refused. A full-control handle is opened before applying the ACL, so insufficient access fails before the .NET file-security write. Standard allow/deny ACEs are supported; other ACE types fail closed. SDDL comparisons normalize Windows-managed AI/AR flags and the order of commutative same-kind ACE blocks, while preserving deny/allow and inheritance ordering. SACL and privilege escalation are unsupported. A DACL removing the operator's access can prevent subsequent verification/restoration; the encrypted prepared entry remains available but cannot bypass Windows permissions.

Existing application configuration files can be reviewed and changed as complete files within these bounds. Planned file creation/deletion, service configuration, arbitrary commands, new registry values and generalized application rollback are not implemented. File writes are flushed but not an atomic filesystem transaction: power loss can leave partial content and a restore conflict requiring manual recovery. Path and ACL checks cannot prevent an administrator replacing ancestors concurrently. No automatic retry or background mutation occurs.

Local and remote execution use a dedicated bounded PowerShell worker with a constant command-line bootstrap; scripts and large payloads travel over stdin. It enforces 120 seconds per invocation, retains at most 2 MiB stdout and 16 KiB stderr, and drains excess output without growing memory. The ordinary operations queue's 128 KiB limit is unchanged. Transport errors and raw payloads are not added to incident records. Timeout/disconnect can leave a remote outcome unknown: reload the encrypted journal and inspect the live target before repeating an action.

Explicit selected-profile binding records a profile ID only when its host matches and uses a direct route. Editing the host or enabling its gateway clears binding. Local and manually entered targets remain unbound. Verified apply timestamps survive restoration, retaining both original change and later recovery in incident reconstruction.

Tests use an in-memory backend for drift refusal, restore, interrupted-action recovery, journal-failure prevention, encrypted persistence and bounded/injection-resistant scripts. Windows integration hooks use only unique temporary files/journals and a unique HKCU key: a full 1 MiB apply, externally deleted-file recovery with original ACL, DACL inheritance apply/drift/restore, and all six registry kinds including high-bit unsigned integers. No remote mutations are run by these tests.
